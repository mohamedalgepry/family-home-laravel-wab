# قائمة التنفيذ الفنية: Checklists لكل نقطة من مراجعة الموقع

## 1) هدف الملف

هذا الملف يحول نتائج المراجعة إلى قائمة تنفيذية قابلة للقيام مباشرة، مع تقسيم كل نقطة إلى مهام صغيرة جدًا، مع معيار قبول واضح، وأولوية تنفيذية، ونتيجة متوقعة.

التركيز هنا على التنفيذ العملي لا على التحليل فقط.

---

## 2) أولويات التنفيذ

### P0 - عاجل ومؤثر جدًا
- تبسيط الصفحة الرئيسية
- تحسين فرز ونتائج البحث
- تبسيط تجربة الهاتف
- مراجعة الأمان على uploads / authorization
- smoke test قبل النشر

### P1 - مهم جدًا
- تحسين التنقل وبنية المعلومات
- تحسين الإشعارات وتخفيف التكرار
- لوحة الإدارة المتوسطة/الخبرة
- تحسين accessibility الأساسية

### P2 - تحسين مستمر
- SEO content quality audit
- performance profiling فعلي
- تحسين metadata وتكوين pages

---

## 3) Checklist - الصفحة الرئيسية

### الموضوع: تقليل كثافة الصفحة الرئيسية

#### المهمة 1: إعادة تصميم التسلسل الهرمي للصفحة
- [ ] تحديد هدف الصفحة الرئيسي: البحث أولاً
- [ ] إبقاء Hero + Search كأولوية رقم 1
- [ ] تقليل عدد العناصر السريعة على الهاتف إلى 3-4 عناصر فقط
- [ ] إبقاء Areas ضمن Section منفصل ومحدد
- [ ] إبقاء Projects و Latest Units كأقسام ثانوية للـ discovery

معيار القبول:
- عند فتح الصفحة، يرى المستخدم خريطة واضحة: Search → Areas → Listings
- لا تظهر أكثر من 3 عناصر تفاعلية رئيسية في أول الشاشة على الهاتف

#### المهمة 2: تبسيط أول نسخة من الصفحة
- [ ] إضافة spacing أكبر بين الأقسام
- [ ] تقليل عدد الأزرار داخل بطاقة الوحدات/المشاريع
- [ ] رفع الحيود البصرية بين الأقسام
- [ ] تقليل عدد الحقول على الصفحة الرئيسية إلى الحد الأدنى

معيار القبول:
- يقرأ المستخدم cued hierarchy دون أن يشعر بالضغط

#### المهمة 3: تحسين تجربة الهاتف
- [ ] اختبار الصفحة على شاشات 375px و 390px و 768px
- [ ] تقليل عدد القوائم الرأسية المكدسة
- [ ] تحويل بعض العناصر إلى carousel / accordion
- [ ] اختبار الـ CTA الذي يفتح البحث من الصفحة الرئيسية

معيار القبول:
- تكون الصفحة قابلة للتصفح بسهولة في الهاتف بدون احتياج لتصفح طويل أو حركتين متعددة

---

## 4) Checklist - التنقل وبنية المعلومات

### الموضوع: جعل الفئات واضحة

#### المهمة 1: إعادة توضيح أسماء الأقسام والروابط
- [ ] تحديد الفئات الأساسية: Home / Units / Projects / Areas / Deals
- [ ] حذف أو إخفاء الروابط المتشابهة
- [ ] توحيد جميع القوائم مع نفس المعنى في كل صفحة

معيار القبول:
- المستخدم يعرف عند النقر على أي رابط ما هو الشيء الذي سيشاهده

#### المهمة 2: تحسين مسار الأنشطة الموصى بها
- [ ] توجيه المستخدم من الصفحة الرئيسية إلى البحث مباشرة
- [ ] ربط المناطق مباشرة بقسم العقارات
- [ ] ربط المشاريع مباشرة إلى صفحة المشاريع

معيار القبول:
- كل زر متاح يفتح مسارًا واضحًا وغير متضاربًا

#### المهمة 3: مراجعة الشريط العلوي
- [ ] تقليل عدد عناصر nav إلى 5-6 فقط
- [ ] حذف الروابط الثانوية المكررة
- [ ] جعل الخيارات الأكثر طلبًا في الواجهة الأولى

معيار القبول:
- لا يتجاوز عدد العناصر الرئيسية 6 بنود

---

## 5) Checklist - البحث والعقارات

### الموضوع: تقوية البحث مع الحفاظ على البساطة

#### المهمة 1: إضافة فرز واضح للنتائج
- [x] إضافة `sort` داخل query params (`UnitController::FILTERABLE`)
- [x] دعم أكواد `newest`, `price_asc`, `price_desc`, `size_desc` — تُترجم إلى (عمود + اتجاه) ثم تمر عبر `ListingQueryBuilder::applySort` بقائمة سماح
- [x] ربط الفرز في URL مع الحفاظ على الفلاتر الحالية
- [x] عرض الخيارات في UI (select في صفحة النتائج) مع «المميز أولاً» كخيار افتراضي

معيار القبول:
- المستخدم يمكنه الفرز من السهل دون أي غموض

#### المهمة 2: إعادة تصميم شريط البحث على الهاتف
- [ ] إبقاء حقل بحث أساسي فقط في أول شريط
- [ ] زر "فلترة" منفصل
- [ ] تأجيل الفلاتر المتقدمة إلى panel منفصل
- [ ] تجنب ظهور كل الفلاتر في نفس الشاشة

معيار القبول:
- لا يتجاوز عدد الحقول الظاهرة في الهاتف 2-3 عناصر في الواجهة الأساسية

#### المهمة 3: تحسين النتيجة نفسها
- [ ] إضافة label صغير "النتائج مرتبة بحسب..."
- [ ] قياس مقدار الأنشطة في كل فحص
- [ ] إضافة حالة "لا توجد نتائج" واضحة ومباشرة

معيار القبول:
- المستخدم يعرف لماذا النتيجة حصلت بهذه الطريقة

#### المهمة 4: التحقق من بناء الاستعلام
- [ ] التأكد من أن كل filter يمر بشكل صحيح في query string
- [ ] التحقق من preserveState عند الانتقال بين الصفحات
- [ ] التحقق من reset filters

معيار القبول:
- عند الضغط على back/forward لا يحدث خلل في الفلاتر

---

## 6) Checklist - الأداء

### الموضوع: التحقق الفعلي وليس التخمين

#### المهمة 1: قياس الأداء الأساسي
- [ ] تشغيل Lighthouse على الصفحة الرئيسية
- [ ] تشغيل Lighthouse على صفحة الوحدات
- [ ] تسجيل LCP / CLS / INP
- [ ] مقارنة النتائج مع target thresholds

معيار القبول:
- يوجد رقم فعلي وتقييم واضح لكل صفحة

#### المهمة 2: تقييم الصور
- [ ] مراجعة حجم الصور داخل الصفحة الرئيسية
- [ ] التحقق من أن الصور في grids تستخدم lazy loading
- [ ] إضافة fallback للصور المكسورة
- [ ] تقليل الصور غير الضرورية داخل بطاقات الوحدات

معيار القبول:
- لا توجد صور كبيرة جدًا غير مبررة في الصفحة

#### المهمة 3: تحسين تحميل الصفحة
- [ ] تقليل JS initial bundle في الصفحة الرئيسية
- [ ] مراجعة components التي يتم تحميلها بشكل غير ضروري
- [ ] اختبار network throttling على الهواتف

معيار القبول:
- لا يوجد تحميل غير ضروري في أول render

---

## 7) Checklist - SEO

### الموضوع: جعل SEO موثوقًا وموقعًا في المنطق

#### المهمة 1: مراجعة كل metadata
- [ ] مراجعة title لكل قسم رئيسي
- [ ] مراجعة description لكل page core
- [ ] التأكد من وجود Open Graph و Twitter Cards
- [ ] التأكد من وجود canonical بشكل صحيح

معيار القبول:
- لا توجد صفحة بدون title/description مناسب

#### المهمة 2: structured data للعقارات
- [ ] إضافة schema type مناسب للعقار
- [ ] تضمين السعر، المنطقة، النوع، الصور
- [ ] التحقق من النمط الصحيح للـ JSON-LD

معيار القبول:
- كل صفحة عقار تحتوي على structured data صالح

#### المهمة 3: indexability
- [ ] إعداد sitemap
- [ ] مراجعة robots.txt
- [ ] منع الفهرسة للصفحات المكررة والمجهولة

معيار القبول:
- لا توجد صفحات غير مرغوب فيها تُفهرس بشكل عشوائي

---

## 8) Checklist - الأمان

### الموضوع: تعميق الأمان دون تضخيم التعقيد

#### المهمة 1: مراجعة SecurityHeaders
- [ ] مراجعة CSP الحالية في الإنتاج
- [ ] إزالة `unsafe-inline` إن أمكن
- [ ] التأكد من أن كل مصدر خارجي مذكور بدقة
- [ ] فحص `report-uri` و `report-to`

معيار القبول:
- لا توجد سياسة CSP واسعة جدًا في الإنتاج

#### المهمة 2: تأمين uploads
- [ ] التحقق من allowed extensions
- [ ] التحقق من MIME type
- [ ] حفظ الملفات في storage مع naming آمن
- [ ] منع الملفات التنفيذية من الوصول المباشر

معيار القبول:
- لا يمكن تحميل ملف غير مسموح به

#### المهمة 3: ثغرات authorization
- [ ] مراجعة كل Route/Admin action
- [ ] التأكد من وجود policies لكل model
- [ ] التحقق من أن frontend لا يحدد التفويض وحده
- [ ] اختباره عبر requests غير مصرح بها

معيار القبول:
- لا توجد route حساسة يمكن الوصول إليها دون تحقق server-side

---

## 9) Checklist - نظام الإشعارات

### الموضوع: تقليل التكرار وتحسين القيمة

#### المهمة 1: مراجعة payload
- [ ] فحص جميع أنواع الإشعارات
- [ ] التأكد من وجود type واضح لكل إشارة
- [ ] التحقق من أن data لا يحمل حقولًا غير مطلوبة

معيار القبول:
- كل إشعار يحمل معلومات كافية لعرضها بدون إعادة الاستعلام غير الضروري

#### المهمة 2: تجميع الإشعارات المتكررة
- [ ] إذا كانت نفس الوحدة تحصل عليها عدة إشعارات، تجميعها في إشعار واحد
- [ ] إضافة summary بديل على أعلى قائمة الإشعارات
- [ ] تقليل التكرار في UI

معيار القبول:
- لا يملأ المستخدم نفس النوع من الإشعارات المتكررة في نفس الوقت

#### المهمة 3: cache control
- [ ] مراجعة cache key لكل مستخدم
- [ ] ضبط invalidation عند markAsRead / delete / create
- [ ] التحقق من استخدام versioning في cache

معيار القبول:
- لا تظهر إشعارات قديمة أو مكررة بعد القراءة

#### المهمة 4: UX الإشعار
- [ ] تصميم قائمة إشعارات أكثر وضوحًا
- [ ] إبقاء actions على العناصر المهمة فقط
- [ ] تقليل عدد العناصر في dropdown

معيار القبول:
- يمكن للمستخدم فهم قائمة الإشعارات من أول نظرة

---

## 10) Checklist - لوحة الإدارة

### الموضوع: جعل الإدارة أكثر تركيزًا وأقل إرباكًا

#### المهمة 1: إنشاء dashboard summary
- [ ] إضافة صفحة رئيسية خاصة للـ admin
- [ ] عرض إجمالي الوحدات، المشاريع، الطلبات، النشاط
- [ ] تنسيق dashboard بالأرقام الأساسية

معيار القبول:
- عند دخول المسؤول يراه كملخص مدير وليس قائمة مجردة

#### المهمة 2: تجميع الروابط
- [ ] تجميع الروابط إلى Categories: Listings / Users / Content / Settings
- [ ] تقليل الروابط الظاهرة في sidebar
- [ ] وضع الروابط الثانوية في قائمة "أكثر"

معيار القبول:
- لا يوجد sidebar مملوء جدًا

#### المهمة 3: panel الإشعارات المنفصل
- [ ] نقل الإشعارات إلى panel واضح ومفصول
- [ ] عدم ربطها مباشرة بكتلة nav الطويلة
- [ ] تمكين action fast path

معيار القبول:
- الإشعارات لا تشتت العرض الأساسي للـ admin

---

## 11) Checklist - Accessibility

### الموضوع: التحقق الفعلي لا الافتراض

#### المهمة 1: تشغيل audit فعلي
- [ ] تشغيل Lighthouse Accessibility
- [ ] تشغيل axe إذا متاح
- [ ] فحص contrast ratio
- [ ] فحص keyboard navigation

معيار القبول:
- يوجد تقرير فعلي بتقييمات تُظهر القضايا الحقيقية

#### المهمة 2: إصلاح نقاط الوصول الأساسية
- [ ] إضافة focus-visible لبعض الأزرار والروابط
- [ ] التحقق من button labels
- [ ] مراجعة modal/dialog accessibility
- [ ] التحقق من الحقول/forms in mobile

معيار القبول:
- لا يوجد زر أو حقل بلا label أو focus واضح

#### المهمة 3: ترميم العبارات المفهومية
- [ ] مراجعة explicit labels for filters and actions
- [ ] تقليل reliance على الأيقونات وحدها
- [ ] التأكد من أن كل action له تفسير نصي

معيار القبول:
- يمكن للمستخدم فهم كل حدث بدون الاعتماد على اللون فقط

## 12) Checklist - QA و Smoke Test

### الموضوع: تجهيز Release Readiness

#### المهمة 1: smoke test في الصفحة الرئيسية
- [ ] التحقق من ظهور Hero بوضوح
- [ ] التحقق من أن Search يعمل
- [ ] التحقق من أن الروابط الأساسية تفتح
- [ ] التحقق من أن Latest Units تتعرض بشكل صحيح

معيار القبول:
- الصفحة الرئيسية تعمل بدرجة إنتاجية قابلة للنشر

#### المهمة 2: smoke test صفحة العقارات
- [ ] فتح صفحة الوحدات
- [ ] التحقق من الفلاتر
- [ ] التحقق من فرز النتائج
- [ ] التحقق من Pagination

معيار القبول:
- الصفحة الأساسية للبحث تعمل بدون أخطاء في UI أو query params

#### المهمة 3: smoke test لوحة الإدارة
- [ ] التحقق من login/admin access
- [ ] التحقق من الإشعارات
- [ ] التحقق من إدارة الوحدات/المشاريع
- [ ] التحقق من forms والـ actions

معيار القبول:
- الوظائف الأساسية في الإدارة تعمل دون خلل حرج

#### المهمة 4: smoke test الهاتف / RTL
- [ ] اختبار الشاشة في العربية
- [ ] اختبار الشاشة في الإنجليزية
- [ ] التحقق من الاتجاه RTL/LTR
- [ ] التحقق من مشاكل overflow

معيار القبول:
- الصفحة تعمل بشكل صحيح في الاتجاهين وأحجام الشاشات المهمة

## 14) معيار النجاح النهائي

يُعتبر المشروع جاهزًا للانتقال إلى مرحلة الإنتاج عندما تكون جميع البنود التالية موجودة:

- [ ] الصفحة الرئيسية واضحة ومركزية
- [ ] البحث فعال وسهل
- [ ] نتيجة النتائج مرتبة وواضحة
- [ ] الهاتف يعمل بشكل متوازن
- [ ] الأمان لا يعتمد على الواجهة وحدها
- [ ] الإشعارات قابلة للفهم دون إرهاق
- [ ] accessibility الأساسية مكتملة
- [ ] QA smoke tests تكتمل بنجاح

---

## 15) الخلاصة

المشروع ليس بحاجة إلى بناء كامل، بل إلى سيطرة دقيقة على أولويات التحسين. هذا الملف يضع كل نقطة في نموذج قابل للتنفيذ، بحيث يمكن للـ team أو صاحب المشروع تحويل المراجعة إلى حركة عمل عملية يومية وفعالة.
